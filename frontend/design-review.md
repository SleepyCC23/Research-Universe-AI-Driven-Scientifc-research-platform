# 研宇宙 · 设计合理性 & 易用性审查报告

> 审查对象：`research-universe/` 全部 18 个界面 + 6 类弹窗 + 全局框架
> 审查方法：逐页走查实现代码与 Mock 数据 → 交叉验证跨页状态是否一致（凡标 ⚠️【实测】的均为我在代码里核实过的真实缺陷，不是主观猜测）→ 按「对用户的实际伤害」分级
> 分级口径：
> - **P0 阻断/误导**：会让用户做出错误决策、丢失数据、或以为生效其实没生效
> - **P1 明显不便**：高频操作摩擦大，用户会抱怨但能忍
> - **P2 体验优化**：可用但有改进空间
> - **P3 一致性/工程**：不直接伤用户，但会持续制造混乱
> - **A11y**：无障碍与响应式

## 一、P0 阻断级问题（10 条）

### P0-1 数据定级有两个入口、两套状态，互不相通 ⚠️【实测】
- **位置**：P16 上传数据「数据分级与合规」 / P10 项目设置「请选择您的数据类型」
- **实测证据**：P16 读的是 `useDataFlowStore.detectedDataLevel`（初始值来自 `UPLOAD_DATA`），点卡片**立即改本地态**；P10 读的是 `useSettingsStore.draftDataLevel / savedDataLevel`。两个 store 之间没有任何同步。
- **对用户的伤害**：在 P16 把项目改成 L2，切到 P10 仍显示 L1；反之亦然。而 L2 会强制禁用 YOLO、拦截原始数据导入、阻断导出——用户以为自己已经切到 L2（更安全），实际业务规则还是 L1，**这是合规事故级的问题**。
- **建议**：定级只保留 P10 一个权威入口（P16 改为只读展示 + 「去项目设置修改」链接），或两处共用同一个 store 且 P16 的修改必须显式「保存」并提示去向。

### P0-2 P16 改定级没有保存动作，改完就「看起来生效了」 ⚠️【实测】
- **位置**：P16「请选择您的数据类型」三张卡片
- **现象**：点击即选中（蓝框+实心圆点），页面上**没有**保存按钮，也没有「未保存」标记；真正落库的动作在 P10。
- **对用户的伤害**：用户选完 L2 直接点「下一步：变量识别」，以为生效了。切页后状态复位。
- **建议**：若保留 P16 可改，则必须加「保存定级」+ 脏状态提示；否则改为只读。

### P0-3 「跳过逐条确认（YOLO）」散落两处、各自独立 useState ⚠️【实测】
- **位置**：P03 文献综述右栏（`strictMode`） / P16 上传数据（`strictConfirm`）
- **实测证据**：两个都是页面内 `useState`，**既不入 store 也不落库**，切换路由即重置为默认值。
- **对用户的伤害**：用户以为这是项目级开关（它决定核验失败是否阻断流程并计入披露报告），实际每次进页面都悄悄恢复成「严格模式」；反过来，用户特意关掉后刷新又打开，会反复被阻断，体验与预期完全不符。
- **建议**：提升为项目级配置（store + 落库），两处共用；UI 上明确写成「项目级设置」并给出披露影响提示。

### P0-4 P03 「已选文献集 12 篇」看不到是哪 12 篇，也无法取消 ⚠️【实测】
- **位置**：P03 右栏「已选文献集」
- **实测证据**：只渲染一个数字、一条进度条和「已满足 ≥5 篇」文案，**没有列表、没有展开入口、没有移除按钮**。
- **对用户的伤害**：用户误选一篇想撤掉，只能回到列表里逐条翻找（128 条结果里找回那一篇）；写综述前无法核对引用池包含哪些文献——这是论文写作的基础需求。
- **建议**：数字可点开抽屉/弹层，列出已选条目的标题+期刊+可移除按钮。

### P0-5 P07 「接受建议并修改」按钮文案承诺了动作，实际只改标记 ⚠️【实测】
- **位置**：P07 模拟评审每条意见的操作行
- **实测证据**：点击只把 `handled` 从 `none` 切到 `accepted`，**不会修改任何正文**。
- **对用户的伤害**：学术场景里，用户会以为稿子已被修改，回头发现没改 → 对「AI 帮我改稿」的信任崩塌。
- **建议**：文案改成「采纳此建议（加入修改清单）」；如果要真的改，必须给出 diff 预览 + 逐条确认。

### P0-6 P10 版本回滚风险与提示不匹配 ⚠️【实测】
- **位置**：P10 版本历史
- **现象**：回滚是覆盖项目产物状态的高风险操作，但入口是一个 12px 的浅蓝文字链接，确认弹窗只有一句话；没有 diff 预览、没有「回滚后受影响产物」清单。
- **对用户的伤害**：用户在不了解差异的情况下回滚，可能覆盖掉几天的工作。
- **建议**：回滚前展示「v18 → v17 的差异摘要 + 受影响模块」；链接改为次级按钮，加入风险图标。

### P0-7 P05 切换「AI 全文生成 / AI 辅助撰写」无确认、无行为说明 ⚠️【实测】
- **位置**：P05 顶部模式切换
- **现象**：Segmented 一点即切，旁边只有「两种模式可在同一文档内随时切换」。
- **对用户的伤害**：用户无法预判切换会不会触发全文重写。若真触发，未保存的修改可能丢失。
- **建议**：切换时若已存在内容，弹出说明「切换只影响后续生成，不会重写已有段落」并二次确认。

### P0-8 P17 「确认处理」无法选择处理方式，与文案自相矛盾 ⚠️【实测】
- **位置**：P17 数据质量问题
- **实测证据**：卡片文案写「均需你确认处理方式」，但每个问题只有一个「确认处理」按钮，点击后弹 Toast「已记录处理方式」——**没有任何地方能让用户选处理方式**（剔除 / 插补 / 保留）。
- **对用户的伤害**：用户被要求做决策却无处可选，会产生强烈的不信任感。
- **建议**：每条问题给出 2–3 个可选处理策略（含默认值与推荐理由），记录选择结果。

### P0-9 P08 产物默认全选「就绪项」，包含未复核内容 ⚠️【实测】
- **位置**：P08 产物导出
- **实测证据**：`selectedArtifactIds` 初始化为全部 `ready` 产物；而披露报告里明确存在「自动处置条目未复核数量（当前 14 条）」。
- **对用户的伤害**：用户直接点「导出已选产物」就把 14 条未复核的自动处置内容一起导出投稿，属于学术披露风险。
- **建议**：默认只勾选「已人工复核」的产物；含未复核条目的产物默认不勾选并标注原因。

### P0-10 未认证/未完成学生认证时，价格与权益展示不一致 ⚠️【实测】
- **位置**：P09 定价
- **实测证据**：顶部横幅在未认证时也写「学生版 ¥19/月（含双 Agent 核验额度）」，而三张卡片里学生版价格同样是 `¥19`（Mock 里 `price: 19` 与认证状态无关）。
- **对用户的伤害**：未认证用户看到 ¥19 但下单时可能被要求认证或按原价计算，产生价格争议。
- **建议**：未认证时学生版显示「认证后 ¥19（当前 ¥XX）」或置灰并引导认证。

## 四、跨页一致性缺陷（P3，12 条；标 ⚠️【实测】为已核实）

| # | 问题 | 实测情况 | 影响 | 建议 |
| --- | --- | --- | --- | --- |
| P3-1 | 数据定级双 store ⚠️【实测】 | `useDataFlowStore.detectedDataLevel` vs `useSettingsStore.draftDataLevel` 无同步 | 见 P0-1 | 单源化 |
| P3-2 | YOLO 开关双 useState ⚠️【实测】 | P03 `strictMode`、P16 `strictConfirm` 互不相通、不落库 | 见 P0-3 | 单源化 + 落库 |
| P3-3 | 引用样式交互不一致 | P05 用下拉，P11 用按钮切换，但共用同一 store | 同一设置两种交互，用户困惑 | 统一为下拉 + 实时预览 |
| P3-4 | 「可行性分析」概念重复 | P02 有「三维可行性评分」，P15 步骤条第三步叫「研究可行性分析」且直接跳到 P04 | 用户分不清是不是同一件事 | 统一命名或明确两者关系 |
| P3-5 | 阶段命名不统一 | 「文献综述中 / 文献综述」「投稿截止 / 距投稿」在卡片、步骤条、导航中混用 | 术语漂移累积成理解成本 | 建术语表，UI 文案统一引用 |
| P3-6 | 面包屑层级三套写法 | P02「研究热点 · 项目名」、P03「文献综述 · 项目名」、P14「研究热点·理论驱动 › 领域研究热词」 | 用户无法建立稳定的位置感 | 统一为「项目名 › 模块 › 子页」 |
| P3-7 | 导出中心/项目设置无导航高亮 | 5 个一级 Tab 都不匹配这两页 | 用户不知道自己「在哪」 | 增加「全局功能」高亮规则或面包屑强化 |
| P3-8 | 「双 Agent 核验 96%/99%」无口径 | 无分母样本、无置信区间 | 数字无法被信任，也无法被审稿人质疑 | 注明样本量与统计口径 |
| P3-9 | 期刊画像指标无各自时间戳 | 只有整页 `dataUpdatedAt` | 「审稿周期 8-12 周」可能是两年前的数据 | 每个第三方指标独立标注采集时间 |
| P3-10 | 版面费只给 USD | 无人民币换算、无订阅/开放获取差异说明 | 国内用户无法快速判断成本 | 加币种换算与「订阅模式可免」细节 |
| P3-11 | 中英混排无解释 | `Agent-α/β`、`Prompt`、`.sav`、`Bootstrap` 直接出现 | 非技术向科研用户理解成本高 | 首次出现加中文注释/悬浮解释 |
| P3-12 | Toast 3.6s 自动消失且不可暂停 | 重要错误（导出被阻断、核验失败）一闪而过 | 用户错过关键信息 | 错误级 Toast 不自动消失或支持悬停暂停 |

## 五、可访问性与响应式（A11y，10 条）

| # | 问题 | 说明 | 建议 |
| --- | --- | --- | --- |
| A1 | 图表无文本替代 | P02/P14 折线图、P17 环形图对屏幕阅读器不可读 | 增加 `aria-label` 摘要或数据表切换 |
| A2 | 整卡可点的嵌套交互风险 | P01 卡片 `role="button"` 内若再加按钮会产生嵌套交互问题 | 约束：卡内不再放可聚焦元素，或改为「卡片 + 显式主操作」 |
| A3 | 原生 `<select>` 样式脱离设计系统 | P17 变量角色、P16/P02 筛选下拉 | 统一为受控 Select 组件（含键盘导航与搜索） |
| A4 | 窄屏横向溢出 | P17 变量表 5 列、P09 额度表 4 列无响应式方案 | 小屏改为卡片式列表或横向滚动容器 + 表头吸附 |
| A5 | 移动端几乎未适配 | 内容固定 `max-w-[1200px]` 双栏，仅 P01 有降级 | 明确移动端目标（只读？）或补齐断点 |
| A6 | 颜色承担语义 | 红/绿/橙表示风险与通过，部分位置无图标或文字双编码 | 关键状态一律「颜色 + 图标 + 文字」三重编码 |
| A7 | 焦点管理缺失 | 弹窗打开后未约束焦点在弹窗内、未还原焦点 | 加 focus trap 与 `aria-modal` |
| A8 | 骨架屏与真实布局尺寸不一致 | 骨架高度与最终卡片高度差异较大，加载完成会跳动 | 骨架按最终尺寸占位 |
| A9 | 步骤条在三个页面重复且占高 | 窄屏被挤压 | 窄屏折叠为「步骤 2/3」简写 |
| A10 | 无键盘快捷键 | 高频操作（检索、确认、下一步）都要鼠标 | 补 `Enter` 提交、`⌘/Ctrl+Enter` 确认等 |

## 七、需要产品决策、我不宜单方面改的 5 项

1. **「左侧边栏 vs 顶部导航」的全局入口归属**——当前两者并存（顶栏右侧 + 可选侧栏），长期看是重复入口，需要定一个。
2. **写作页方法章节「不可修改」是否过严**——投稿时常需按期刊格式改写方法描述，是否允许「生成可编辑副本」。
3. **导出格式单选是否过强**——一个产物同时要 docx + PDF 是常见需求，是否改为多选。
4. **「匹配度 / 准确率 / 录用率」百分数的披露口径**——涉及合规表述边界，需与法务/学术团队对齐后再统一文案。
5. **移动端支持范围**——是「不做」还是「只读」，直接决定工作量量级。

## 八、做得不错、建议保持的部分

- 未验证文献的强隔离（不可选入 / 不可插入 / 不入参考文献表 / 阻断导出）闭环完整，且错误码与前端拦截一致。
- 不可逆操作都带二次确认，且弹窗里写明留痕位置，这个习惯很好。
- 异步任务统一走一套三态弹窗，交互一致。
- 期刊画像区强制标注「来源 + 样本量」，超期标注「数据待确认」，是可对外交付的严谨度。
- 空态 / 错误态 / 骨架屏三个组件被所有列表页复用，没有各写一套。
