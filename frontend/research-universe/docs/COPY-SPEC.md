## 一、审核方法

1. **扫描**：对 `src/**/*.tsx` 与 `src/mocks/db.ts`（文案真源）做两轮正则扫描，命中的候选人工判定「用户可见 / 仅注释」；
2. **判定**：只看**用户能看到的那句话**——注释、类型文档、接口路径不属于文案，不参与替换；
3. **落地**：写入明确的**替换表**（原句 → 新句，精确整句匹配，不用片段替换，避免伤到代码标识符），由 `tools/copy-sweep.js` 一次性执行并输出「替换处数 / 未命中 / 次数异常」；
4. **回归**：`tsc --noEmit` + `vite build` 双通过后，再跑一轮扫描确认无残留。

## 二、五条表达原则

| # | 原则 | 反例（本次实际清理过的） | 正例 |
| --- | --- | --- | --- |
| 1 | **说用户的事，不说我们的实现** | 遇 Retry-After 自动退避并提示重新授权 | 写入失败会自动重试，需要重新授权时会提示你 |
| 2 | **说清「会发生什么」，不说「机制是什么」** | 沙箱执行预计 1-3 分钟，异步返回结果 | 分析预计需要 1–3 分钟，完成后会自动通知你 |
| 3 | **不暴露内部代号**（页面编号 / 字段名 / 变量名 / run_id） | 改级将同步影响：P4 数据导入拦截、G2 跳过逐条确认禁用、G3 导出阻断 | 改级后立即生效：数据导入会被拦截、「跳过逐条确认」会被禁用、导出会被阻断 |
| 4 | **用研究者的话，不用数据库的话** | 字符串字段 major 为自由文本 | 变量「专业」是自由填写的文本 |
| 5 | **给下一步，不给结论** | 分析执行失败（到此为止） | 分析执行失败，请稍后重试（必要时补「可先用示例数据体验」） |

## 三、术语禁用表（技术词 → 用户语言）

### 3.1 实现与系统术语

| 禁用 | 替换为 | 说明 |
| --- | --- | --- |
| Retry-After、退避、重试策略 | 自动重试 / 稍后重试 | HTTP 头名与算法名一律不出现在文案里 |
| 沙箱（沙箱执行 / 沙箱算力 / 隔离沙箱） | 分析（分析执行 / 分析算力 / 项目内隔离解析） | 「沙箱」是安全机制名；用户关心的是「安全、不出去」 |
| 异步（异步执行中 / 异步返回） | 进行中 / 完成后会自动通知你 | 同步异步是调度实现，不是用户概念 |
| 兜底（免授权兜底 / 不做兜底给分） | 无需授权也能用 / 不会给出猜测性的分数 | 「兜底」是工程口语 |
| 降级 | 改为 / 简化 | 视语境：`降级为推测性表述` → `改为推测性表述` |
| 轮询、幂等、乐观更新、熔断、限流、队列 | （不出现） | 若必须表达状态，用「正在处理 / 稍后自动更新」 |
| 落库、持久化、写入成功 | 已保存 | |

### 3.2 数据与字段术语

| 禁用 | 替换为 | 说明 |
| --- | --- | --- |
| 字段（敏感字段 / 字符串字段） | 信息 / 变量（敏感信息 / 变量「专业」） | 研究者的心智是「变量 / 取值」，不是「字段」 |
| 字段语义歧义清单 | 变量含义待确认 | |
| run_id / 绑定 | 运行记录 / 关联 | 允许保留编号值本身（用户可能要引用它核对） |
| 公开队列 | 公开数据集 | |

### 3.3 内部代号（严禁出现）

`P4` / `G2` / `G3` / `P05` / `P11` 等**页面编号**、`DataUploadData` / `detectedDataLevel` 这类**字段名**、`a7f3-20260921-0912` 这类**内部主键**（如确有必要展示，前面必须加「编号 / 记录号」等人话标签）。
> 本次清理了 3 处外泄：动态修改记录里的「P4 数据分析页」「绑定 run_id」，合规提示里的「P4 / G2 / G3」。

## 四、错误与状态文案规范

### 4.1 错误提示三要素（缺一不可）

```
[发生了什么] + [对你的影响] + [下一步怎么做]
```

| 场景 | 合格写法 |
| --- | --- |
| 分析执行失败 | 分析执行失败 + 结果未生成，已保留上次结果 + 请稍后重试；连续失败可在「项目设置」切换方法 |
| 导出被阻断 | 有 2 条引用未通过核验 + 无法导出投稿包 + 去「文献综述」处理这 2 条 |
| 未验证文献不可选 | 未验证条目不可选入 + 不会进入参考文献表 + 先在「文献综述」完成核验 |

**禁止**：只报错不给下一步（如「请求失败」）；把错误码直接抛给用户（错误码可放在「详情」里供反馈时引用）。

### 4.2 状态措辞统一表

| 状态 | 统一用词 | 不建议 |
| --- | --- | --- |
| 加载中 | 正在加载… / 正在执行分析… | 加载、loading、处理中 |
| 任务运行中 | 进行中（例：双 Agent 核验进行中，预计 1–3 分钟） | 异步执行中、running |
| 已完成 | 已完成 / 已通过 | done、成功 |
| 空态 | 还没有…（例：当前项目还没有阶段产物） | 暂无数据、无数据 |
| 不可用 | 数据不足，未评分 | N/A、-、0 分 |
| 已保存 | 已自动保存 11:24 | saved |

## 六、设计令牌（交付前端的唯一真源）

> 令牌定义在 `tailwind.config.js`，本节为可读版本；组件必须引用令牌，**不得写死色值**。

### 6.1 颜色

| 语义 | 令牌 | 值 | 用途 |
| --- | --- | --- | --- |
| 页面底色 | `page` | `#F5F7FA` | 全局背景 |
| 卡内嵌面板 | `panel` | `#EEF1F6` | `.ru-panel` 底 |
| 描边（常规 / 加重） | `line` / `line-strong` | `#E6EAF2` / `#D5DCE7` | 卡片、输入框、分隔线 |
| 主文本 | `ink` | `#1F2733` | 标题、正文 |
| 次级文本 | `ink-2` | `#5A6473` | 说明、表单标签 |
| 弱文本 | `ink-3` | `#8C96A8` | 提示、占位、脚注 |
| 品牌主色 | `brand` | `#2563EB` | 主按钮、链接、选中态、关键词高亮 |
| 品牌悬停 / 浅底 / 浅描边 | `brand-hover` / `brand-soft` / `brand-line` | `#1D4ED8` / `#EFF4FF` / `#BFD3FF` | |
| 成功 | `ok` / `ok-soft` / `ok-line` | `#16A34A` / `#E9F8EF` / `#B7E7C9` | 通过、已完成 |
| 警示 | `warn` / `warn-soft` / `warn-line` | `#D97706` / `#FFF6E6` / `#FBE0B0` | 临近 DDL（≤7 天）、待处理 |
| 危险 | `danger` / `danger-soft` / `danger-line` | `#DC2626` / `#FDECEC` / `#F7C6C6` | 阻断、删除、L2 强制项 |
| 辅助色 | `violet` / `teal`（各带 soft / line） | `#7C3AED` / `#0EA5A5` | 图表序列、标签分类 |

**用色规则**
1. 一屏内**主色只用于「当前可点的最重要动作」**，同一区块不得出现两个 `brand` 实心按钮；
2. 状态色只表达状态，不表达装饰：`danger` 用于阻断与不可逆操作，`warn` 用于「需要你注意但不阻断」；
3. 关键词高亮（如 DDL 行的「短视频：」）与链接同用 `brand`，`：` 用 `ink-3` 弱化；
4. 深浅色对比：正文 `ink`，说明 `ink-3`；**不得用 `line-strong` 当文字色**。

## 七、组件标注规范（文案位与状态）

| 组件 | 文案位 | 规则 | 状态 |
| --- | --- | --- | --- |
| **卡片 `Card`** | `title` / `note` / `extra` | 标题≤12 字；`note` 放「口径与来源」（如「全局横切规则 · 三处共用」），不放装饰性描述 | 默认 / 空态 / 加载（骨架屏） |
| **按钮 `Button`** | 主文案(动宾) / `loading` 文案 | 用动词短语：保存定级、执行分析、生成投稿检查清单；**loading 时文案变「创建中 / 保存中」并禁用** | 默认 / hover / 加载 / 禁用 / 危险 |
| **标签 `Tag`** | 2–6 字 | 状态标签（已通过 / 待核验）+ 必要图标；同屏不超过 2 种语义色 | 6 色语义 |
| **提示条 `InfoBanner`** | 一句话 | `tone=warn` 说「会有什么影响」，`tone=danger` 说「为什么不能做」 | info / ok / warn / danger |
| **弹窗 `Modal`** | 标题 + 正文 + 页脚双按钮 | 不可逆操作必须写清**留痕位置**与**恢复方式**；确认按钮文案＝动作本身（如「确认注销」），禁用「确定」 | 默认 / 危险确认 |
| **Toast** | `title` + `description` | title 说结果（已保存 / 已切换），description 说影响或下一步；**不得只写「操作成功」** | ok / warn / danger / info |
| **空态 `EmptyState`** | 标题 + 说明 + 一个主按钮 | 句式「还没有 X」＋「怎么产生 X」＋ 主按钮 | 空 / 无权限 / 出错 |
| **加载态** | 骨架屏 / 文案 | 列表用骨架屏；按钮用 loading；整体加载写「正在加载…」 | |
| **表格 `Table`** | 表头名词（变量 / 类型 / 状态），单元格值 | 表头不加「：」；数值右对齐；空值显示「—」 | 空 / 加载 / 行选中 |
| **表单** | 标签 + 占位 + 错误 | 标签用名词，占位放示例值（不重复标签）；错误写在字段下方并说明如何修正 | 默认 / 错误 / 禁用 / 已保存 |

## 十、给前端的落地要求

1. **文案不进组件**：所有用户可见文案来自接口载荷或 `src/mocks/db.ts`，组件内不写业务文案（文案变更不应发版）；
2. **新增文案先过本规范**：新增任何用户可见字符串，按 §二 五条原则与 §三 禁用表自检；
3. **令牌不写死**：颜色/字号/圆角/阴影一律用令牌类名，禁止 `#xxxxxx` 字面量（图表内联色除外）；
4. **改文案必须同步三处**：`src/mocks/db.ts`（或接口载荷）+ 本文档 §八 清单 + `docs/VARIABLES.md` 的字段说明。
